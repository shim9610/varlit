Mapped-array supplement totals include two scans; primary array totals include one. Do not compare those totals as equal work. Stream arrays do not perform unsupported point/range queries, so their shorter completion is not an equal-work comparison with other array modes. Only equivalent operation ratios are shown. Array ratios use the best complete SQLite candidate across physical block sizes for the same logical samples. SQLite mmap recheck ratios keep the same cohort, physical group size and one complete SQLite configuration selected by completion for every metric. Hover over a ratio for its baseline profile. Independent read-check rows are a separate before/after/mode cohort; their New Full / selected row ratios divide the new runtime’s FULL median by the selected row for the same workload. Before/main rows retain their own runtime. Values above 1 mean the selected row took less time. They are observations, not a 5% qualification or a new SQLite comparison. Calibration, payload API diagnostics and retained alerts. PSS is sampled in separate process-tree resource runs normally every 50 ms (fast cases at 5 ms) and can miss brief peaks. Temporary and deleted-open columns are separate maxima and must not be added as a simultaneous peak. File-cache/cgroup baselines and RSS are retained in the JSON. Refused profiles remain visible and are not assigned invented timing values. SQLite mmap recheck includes record windows and confirmed-prefix snapshots during append. Snapshots copy the captured index when rebuilt; no claim of constant-cost indefinite refresh is made. Primary and snapshot live cohorts remain separate. Mapped extents are sampled virtual file offsets, deduplicated across processes; they are not resident memory or proof that a read used mmap. During-write % counts only complete consume intervals within the writer window for the least-advanced reader.
