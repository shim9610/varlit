# Verification tools and recorded results

This guide follows the current repository. The documentation gate rejects repeated
report sections, checks local links and executes the grouped-block quickstart from
its actual Markdown source. Historical reports identify the
revision they tested; a successful older run is not a result for a newer commit.
The production runtime at `851836e` passed all **69 CI jobs** and all **three
Sanitizers jobs**:

- [CI, including the strict required gate](https://github.com/shim9610/varlit/actions/runs/41892694910)
- [Miri, AddressSanitizer/leaks and fuzz smoke](https://github.com/shim9610/varlit/actions/runs/41892694877)

`ci / required` includes native tests, feature interactions, executable API
contracts, storage/resource contracts, package/docs checks, CodeQL, dependency
checks and the reusable `verification.yml` jobs. Sanitizers is a separate
workflow, not a dependency of that aggregate. Check both workflows on the exact
candidate commit. See [contributor checks](../CONTRIBUTING.md#local-checks).

## Native tests, API contracts and failure recovery

CI tests default and all features on Linux, Windows and macOS, with bounded-I/O
checks on each platform. macOS currently uses one `macos-15-intel` runner with
separate required steps for those checks; this is not ARM64 coverage. Linux also
runs discovered single features and pairwise feature interactions. Pairwise and
all-feature runs do not enumerate every possible higher-order feature subset.

New or changed public interfaces require executable valid/invalid contracts in
[the frozen-inventory gate](validation-contracts.md). Independent consumer,
renamed-dependency, Rust 1.95 minimum-version and verified crate-archive jobs
exercise the distributed API and package contents.

Native implementation files share their original module through literal includes.
The syntax-tree inventory and validation-boundary checker inspect included bodies
recursively and preserve the owning API identity. Negative controls reject hidden
source, changed signatures, raw-decoder bypasses and paths outside the crate.
The frozen legacy inventory is not regenerated by source reorganization.

`scripts/check_storage_contracts.py` currently runs 62 exact cases, including
hostile metadata combined with allocation refusal, short/zero reads and
intermediate I/O failure. Tests check finite traversal, cleanup, repair/retry,
writer poisoning, pinned snapshots and independent-reader publication. Expanded
index controls run 160 compound trials and 1,590 hostile-metadata cases across
checked and trusted read policies. These counts are checked evidence, not an
exhaustive input-space claim.

The read-policy suite exercises unset compatibility and four explicit modes,
CRC/structure selection, positional-read counts, decoder/resource refusal,
compression headers, native/indexed/mmap/matrix routes and pending/confirmed
visibility. Explicit verification remains strict when ordinary reads trust
captured metadata. The [policy contract](design/read-validation-policy-review.md)
defines which checks can be omitted.

```sh
python3 -m unittest discover -s scripts/tests
python3 scripts/check_storage_contracts.py --output target/storage-contracts
```

## Successfully generated files

The producer/consumer contract applies to successfully published writer output
that is read without external modification, with the matching format, schema,
endianness and codec contracts. Required companion files must remain together.
Reader limits must admit the requested operation; allocation or I/O failures may
still return their documented errors. Publication visibility and `sync()`
durability retain the contracts of the selected storage mode. A successful
buffered write alone is not a completed publication.

Two Kani harnesses call the actual native record header/footer encoders and
decoders. Every scalar retains its full Rust range. Header encoding requires
`offset + 32 + payload_len + footer_len` to fit in `u64`. Each present footer
predecessor must be nonzero and earlier than the current record. Within those
domains, decoding accepts the encoder output and reproduces every field; header
decoding consumes exactly 32 bytes. An independent wire oracle checks the fixed
field positions and little-endian bytes, so a shared encoder/decoder mistake
cannot pass by round-tripping itself. Reachability checks include an empty payload,
the maximum representable physical end, and both absent and present footer links.
The 32-byte framing bounds implementation loops, not payload size or file length.

These are framing proofs, not a proof of every successful file operation or
payload codec. The generated-file integration regression covers fixed and
variable derived blocks, both endians, scalar bit patterns, field IDs across the
small/large-ID boundary, nested values, publication, writer resume and compatible
CRC/structure read policies. Existing stream/index lifecycle and matrix-reader
regressions cover their respective storage routes. User-defined codecs must
fulfil their own encoding/decoding contracts; a library API cannot certify
arbitrary custom payload bytes merely because it wrote them.

Application developers can run the [qualification template](self-check-guide.md#application-qualification-template)
with ordinary `cargo test`; it needs no proof-tool installation. `run_strict()`
requires every declared type's sample. Generated `check_file()` registers the
format's typed decoders and reports violated or unverified conditions for a
particular quiescent artifact. These runtime checks do not extend the framing
proof to arbitrary codecs or establish all assumptions of a whole-program proof.

Malformed or truncated inputs remain covered by the resource, corruption,
failure-injection and fuzz suites above. Their tested resistance is separate
from the successful-output framing proofs. Existing read-policy bounds and
publication guards remain enabled.

## Coverage

CI uses Rust 1.95.0 with `llvm-tools-preview` and `cargo-llvm-cov 0.9.1`.
Workspace unit/integration tests run with all features. Vendor, integration-test,
example, tool and proof-only paths are excluded from the report; inline unit-test
code inside library source files is still counted. Doctests, ignored tests and
compile-fail snapshots are outside this instrumented measurement. Ordinary CI
checks doctests and compile-fail snapshots separately.

The recorded `851836e` run covers **49,464 / 56,065 lines (88.23%)** and
**78,186 / 90,888 regions (86.02%)**. The report does not measure branch coverage
or enforce a coverage-percentage floor. The job requires successful tests and
report generation; it does not certify every source path.

```sh
cargo install cargo-llvm-cov --locked --version 0.9.1
rustup component add llvm-tools-preview --toolchain 1.95.0
VARLIT_SKIP_UI_SNAPSHOTS=1 cargo +1.95.0 llvm-cov --workspace --all-features --lib --tests --locked --no-report
cargo +1.95.0 llvm-cov report --ignore-filename-regex '/(vendor|tests|examples|tools)/|/src/verification/' --show-missing-lines
```

## Kani

The [contract manifest](verification/proof-contracts.json) currently registers
**78 harnesses in 15 contract groups**. Both default and all-feature builds must
complete their registered set. Equal counts do not make these configurations
interchangeable: feature selection changes compiled implementations.
`scripts/check_proof_contracts.py` rejects missing, duplicate, unexpected or
unfinished harnesses and verifies source fingerprints before and after the run.
A zero-harness run fails.

| Contract group | Harnesses | Main scope |
| --- | ---: | --- |
| Record extent and native framing | 3 | Full-width checked address arithmetic and actual header/footer producer-consumer pairs |
| Observed prefix | 4 | Prefix transitions; bounded membership/truncation models |
| Publication metadata | 5 | Typed frontier/checkpoint validation and actual 24-byte frontier decoder |
| Publication protocol | 9 | Abstract I/O effects and inductive frontier invariants |
| Compression steps | 6 | Block progress and output reservation bounds |
| Limited spill | 2 | Checked extents and bounded partial-write/retry model |
| Chunk parser | 6 | Header/entry/table extent and complete-validator positive witness |
| Materialization | 2 | Budget transition |
| Index visits | 4 | Decreasing traversal fuel and child height |
| Decoder memory | 13 | Charge/transfer, bounded byte-vector decode, arbitrary callback effects and active-frame induction |
| Decoder transitions | 4 | Three full-width numeric contracts and a two-object scope identity model |
| Fallible ownership | 16 | Refusal, partial cleanup and bounded clone/owner models |
| Scalar owner memory | 2 | Selected scalar Box validity and refusal-before-initialization |
| Buffered private row | 1 | A 13-byte row in at most 39 backing bytes |
| Untrusted sequence candidate | 1 | Full-width sequence subtraction and candidate conversion |

Full-width arithmetic proofs and bounded container/I/O models have different
scopes. Bounds, allocator/callback assumptions and exclusions are recorded per
contract. Unwinding assertions remain enabled; an unwind limit is a proof bound,
not a file-size limit. The tests and models do not establish whole-library
out-of-memory (OOM) freedom, arbitrary callback termination or all filesystem
crash schedules.

CI installs Kani 0.68.0 for its C Bounded Model Checker (CBMC) and goto tools,
then builds the pinned upstream
crash fixes at `947fcec757d9b6a2d07283a0952aaa088e1d8df1`. The source still reports
0.68.0, so the version string alone does not identify the qualified verifier.
Use the same setup and strict runner commands from Bash:

```sh
cargo install kani-verifier --locked --version 0.68.0
cargo kani setup
varlit_kani_checkout="${TMPDIR:-/tmp}/varlit-kani-947fcec"
bash scripts/build_memory_kani.sh "$varlit_kani_checkout"
export PATH="$varlit_kani_checkout/scripts:$HOME/.kani/kani-0.68.0/bin:$PATH"
export CARGO_BUILD_JOBS=4 CARGO_INCREMENTAL=0
set -euo pipefail
cargo metadata --locked --format-version 1 > /dev/null
for varlit_features in default all; do
    varlit_flags=()
    if [[ "$varlit_features" == all ]]; then varlit_flags+=(--all-features); fi
    varlit_output="target/verification/$varlit_features"
    mkdir -p "$varlit_output"
    python3 scripts/check_proof_contracts.py --capture "$varlit_output/source-before.json"
    cargo kani -p varlit-core "${varlit_flags[@]}" --jobs 2 --output-format terse --default-unwind 5 -Z stubbing -Z unstable-options -Z function-contracts --harness-timeout 300 2>&1 | tee "$varlit_output/kani.log"
    python3 scripts/check_proof_contracts.py --source-before "$varlit_output/source-before.json" --log "$varlit_output/kani.log" --features "$varlit_features" --output "$varlit_output/contracts.json"
    python3 scripts/check_memory_proofs.py --kani-checkout "$varlit_kani_checkout" --features "$varlit_features" --output "$varlit_output/memory-checks"
done
git diff --exit-code -- Cargo.lock
```

The scalar memory checks qualify two validity harnesses and one
refusal-before-initialization harness, with positive/negative controls.
Whole-owner initialization/value-validity proofs remain in the separately planned
library; they are not counted as a completed Varlit guarantee.

## Closed decoder state transitions

The [state contract](verification/state-transitions.md) defines the decoder and
collection-budget invariants, initialization, permitted transitions and callback
boundary. Kani checks full-width scalar contracts and the actual callback driver.
The compiler gate discovers writes and mutable loans to these owners across the
compiled core, including generic bodies; it does not maintain a hand-written list
of routes from each API. Eleven state writers must remain registered with proofs.
New writers, raw aliases, escaping mutable fields, unchecked codec dispatch and
unmodeled aggregate captures fail. Native syntax checks retain field privacy,
layout, scope authority and sealed callback adapters. Compiler controls deliberately
break these rules and the connection between helper results and committed stores.

This combines semantic transition proofs with structural mutation coverage.
The inductive argument also uses Rust's safe aliasing, privacy and lifetime rules;
the gate is not a verified Rust alias analyzer or a whole-program refinement proof.
The decoder closure covers default and all-feature Linux MIR. Publication, index,
compression and ownership contracts retain their separately listed scopes.

### Decoder boundary performance

An equal-work local comparison against `4eef673` used rebuilt release binaries,
three alternating pairs per workload and six separate resource probes. Each
storage run wrote 512 MiB in 16 MiB epochs. Offline cases scanned data and made
128 point reads and 16 range reads; each live reader verified all 512 MiB.
Native/indexed groups were 64 KiB, streaming groups 1 MiB.

| Workload | Median wall seconds, before → after | Aggregate CPU seconds, before → after | Sampled peak aggregate PSS MiB, before → after |
| --- | ---: | ---: | ---: |
| Native access, one reader | 0.841 → 0.841 | 0.573 → 0.583 | 23.09 → 22.92 |
| Indexed access, four readers | 0.870 → 0.844 | 0.953 → 0.879 | 45.30 → 45.05 |
| Live stream, one writer/four readers | 0.598 → 0.592 | 0.940 → 0.920 | 25.92 → 25.93 |

PSS means proportional set size. The largest wall increase was +0.03%; the
largest CPU increase was +1.64%. Final physical file allocation matched in each
pair; one native resource probe observed an additional transient 4 KiB. The
50 ms probes observed no private temporary-directory or deleted-open workload
storage. Peaks shorter than that interval remain outside the sample guarantee.
Caps stayed at 4 CPU /16 GiB RAM /32 GiB filesystem.

A separate complete-decode campaign used 20 million iterations per run, with
independent checksums consuming every field. Scalar, custom scalar, nested
8-field tuple and custom tuple median times decreased by 74.6%, 35.9%, 60.2%
and 42.8%. Inlining checked primitives and sharing one outer custom-code frame
removed redundant work. These short local comparisons describe the measured
workloads, not a bound for every downstream codec or machine.

## Production callers and future changes

The source-wide `proof_coverage` integration test inventories all three published
crates, including private methods, trait defaults, nested functions, inactive
platform branches and macro generator sources. A compact checked-in
[baseline](verification/production-inventory.json) records every source/config
file and a digest of the complete AST body catalogue. Any change conservatively
requires reviewing **all** proof families. This is change detection, not a proof
that every inventoried body satisfies a specification.

The [caller contracts](verification/caller-contracts.json) additionally record
compiler-resolved protected calls for default and all-feature Linux builds.
`check_proof_bindings.py` reads unoptimized MIR from pinned rustc 1.95.0; unknown
protected resolutions, unregistered indirect references, new/changed callers and
unsupported MIR syntax fail. One existing `Option::map(RecordIndexEntry::checked_physical_end)`
edge has an explicit body-bound indirect contract; it is inventoried, not an
interprocedural refinement proof. Selected result checks follow
`Result`/`Option`/`Try` propagation.
Five default and seven all-feature control-flow obligations require a guard to
precede its effect and prevent a rejected guard from reaching that effect.
These checks cover normal control flow, not unwinding or arbitrary interprocedural
semantics. Other targets and feature combinations retain source-change and native
feature-matrix checks; they do not acquire a MIR refinement proof.

```sh
rustup toolchain install 1.95.0 --profile minimal --no-self-update
export RUSTUP_TOOLCHAIN=1.95.0
cargo test --locked -p varlit --test proof_coverage
cargo rustc --locked -p varlit-core --lib -- --emit=mir=target/default-callers.mir
python3 scripts/check_proof_bindings.py --mir target/default-callers.mir --features default --output target/default-bindings.json
python3 scripts/check_state_transitions.py --mir target/default-callers.mir --features default --output target/default-state.json
cargo rustc --locked -p varlit-core --lib --all-features -- --emit=mir=target/all-callers.mir
python3 scripts/check_proof_bindings.py --mir target/all-callers.mir --features all --output target/all-bindings.json
python3 scripts/check_state_transitions.py --mir target/all-callers.mir --features all --output target/all-state.json
python3 -m unittest discover -s scripts/tests -p test_proof_bindings.py
```

The controls compile valid renamed calls and deliberately broken Rust callers:
ignored/overwritten results (including mutable aliases), late or bypassed guards,
ignored rejection, shadowed helpers, function pointers and generic function-item
dispatch. Rejection is checked against actual compiler MIR,
independently of the frozen caller hashes.

For a source change, first identify the new behavior and its input, callback,
allocation and error obligations. Extend the actual consumer proof or native
regression where its scope requires it. Export candidate source inventory with
`VARLIT_PROOF_INVENTORY_OUT=target/production-candidate.json cargo test --locked -p varlit --test proof_coverage`
and candidate typed callers with the runner's `--observe` option. Export never
bypasses acceptance or rewrites either baseline. Review the differences before
recording the inventory, then require both complete Kani configurations, caller
checks, deliberate-defect controls and native regressions on the final tree.
Each caller family must retain exactly its registered harnesses. Updating a
fingerprint alone supplies no semantic evidence; reviewers must assess the
changed behavior. No finite harness set automatically proves every future edit.

New consumer proofs execute the actual frontier wire decoder, complete bounded
`Vec<u8>` decoding with symbolic allocation refusal, and a 49-byte one-entry
positive witness through the complete chunk structural validator (frame checks
disabled). Header/table helpers retain their separate full-width proofs. A general whole-validator
proof is not established: exploratory attempts timed out at the existing
300-second budget, and additional empty-output experiments were not qualified.
None of these experiments is counted as a completed proof.

## Executable specifications and composed consumers

Every contract family now declares `requires`, `ensures`, `on_error`, `frame`
and `progress` clauses in the manifest. These clauses describe the actual proof
scope and assumptions; prose is not counted as a new proof.

Six actual implementation helpers additionally carry Kani `ensures` contracts:
chunk table extent, compression reservation/block/stream decisions, traversal
height matching and visit fuel. They accept all unsigned input values without
extra file-validity assumptions. Fuel also declares `modifies(remaining)` and
compares the post-state with `old(*remaining)`, so failed admission preserves zero
and success consumes exactly one visit. `proof_for_contract` harnesses check the
real bodies against these executable specifications.

The actual chunk validator uses `stub_verified(table_extent)` in a composed
proof. It covers real input lengths 0..32, fixed valid format fields and chunk
size 1, arbitrary u64 declared output and u32 count. No entry exists in those
inputs. Instrumented entry-read/allocation sentinels must remain unreachable;
only the complete empty container may succeed. This proof includes cases whose
declared count/output agree but whose real table is absent. It does not prove
the complete arbitrary-size/C-zstd parser.

The two new decoder/budget consumers execute two full-width charges around
possibly truncated reads, a returning callback error and trailing input. Nested
decode preserves the parent's backing reference, cursor and limit while
retaining completed charges on every return. Two actual
`MaterializationBudget::decode` calls keep the same remaining ledger across
success, error and retry; the input bound is 18 bytes and the callback terminates
and uses Decoder's read/charge interface. Both endians are checked in nested
decode. These are concrete callback models, not a proof of arbitrary user code.

The native AST gate requires each executable definition, exact annotation set,
`proof_for_contract` target and verified use to match the registry. Every
consumer's callee proof must be registered and complete. Replacing a contracted
helper with an ordinary stub, deleting a contract/proof, introducing an
unregistered semantic stub or making the dependency graph cyclic fails.
Allocator and existing empty-Vec models retain their separately stated
assumptions; an unreachable-call sentinel is an assertion, not an assumption.

Allocated-String experiments exceeded the unchanged 300-second/16-GiB
qualification budget, including verifier OOM kills. They are excluded from the
registered set and do not establish a runtime library OOM or successful String
ownership proof. General Box/Arc/TryClone initialization remains in the separate
library project. No input narrowing or unqualified model is labeled a completed
whole-library proof.

## Publication, recovery and concurrent owners

[Publication qualification](https://github.com/shim9610/varlit/blob/9343ea1754947d3af8e03dfa525d6ba5af856008/docs/verification/publication-20261102/README.md) retains
8,450 torn-head images, all 512 length-three histories over eight stated operations,
16 longer seeded histories and fault-hook interruption with readers held open.
The oracle checks whole confirmed generations, pinned-reader stability, failed
adoption and subsequent recovery/publication. Later compound tests add allocation
refusal, I/O failures and last-owner release.

These checks do not equate `flush()` with publication, a returned write error with
rollback, or process termination with power loss of the OS page cache. Native
commit/checkpoint/resume/follow entry points share statically dispatched protocol
drivers with the proofs. The OS durability, immutable-prefix and callback premises
remain explicit in the linked evidence.

## Loom

```sh
RUSTFLAGS='--cfg varlit_loom -D warnings' cargo run --locked --manifest-path tools/verification/Cargo.toml
```

The isolated runner imports production `scan_control.rs`. Normal builds use a
private triomphe owner and std atomics; the model substitutes Loom ownership and
atomics while retaining the cancellation/progress method bodies. Two finite
models explore cancellation publication/monotonicity and progress-driver checks,
without unbounded spinning or a configured preemption bound. They do not model
triomphe allocation/refcount internals, every single-writer/multiple-reader
protocol or filesystem durability.

The runner refuses a build without `varlit_loom`. Its dependencies have their own
lockfile and advisory audit and are not library runtime dependencies. A retained
negative control changes the release store to relaxed and fails the publication
assertion.

## Miri, ASan and fuzzing

The [self-check guide](self-check-guide.md) gives Miri reproduction commands.
The exact 55 portable-core exclusions have reasons and alternative-coverage gaps
in `scripts/miri-exclusions.json` and `scripts/miri-exclusion-audit.json`.
Supported pure-memory logic is checked separately where possible. Native/ASan
coverage does not provide Miri's interpreter guarantees for excluded OS paths.

Sanitizers also runs fallible-ownership and codec-array Miri tests, ASan with leak
detection, and a 90-second smoke run for every declared fuzz target (currently 13).
The bounded smoke run is not a sustained fuzz campaign. mmap immutability and
external-truncate hazards remain documented in [SECURITY.md](../SECURITY.md).

## Dependency and CodeQL checks

Required jobs run cargo-audit/cargo-deny and
`scripts/check_vendored_advisories.py`, including its synthetic affected/patched
control. The vendored check covers package identities that lockfile auditing
omits for path dependencies. redb 4.4.0 is a development-only oracle. Registry
advisories do not certify local patches or dependency source correctness.

CodeQL runs Rust, Python and Actions queries with a strict Static Analysis
Results Interchange Format (SARIF) result gate.
Extraction/macro limitations remain visible; behavioral and generated-API tests
are still necessary. See [the retained CodeQL follow-up](performance/read-validation-20261104/README.md#ci-evidence-follow-up).

Six CycloneDX 1.5 JSON inventories cover the three publishable crates with default
and all-feature resolution across Cargo targets. Build dependencies are included;
dev dependencies are omitted by the inventory tool. Provenance includes the Git
revision and lockfile hash. These describe dependency configurations, not a
particular compiled binary or a security certification.

```sh
cargo install cargo-cyclonedx --locked --version 0.5.9
cargo fetch --locked
python3 scripts/generate_sbom.py
```
