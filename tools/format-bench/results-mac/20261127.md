## Failures, exclusions, and consistency observations

- Grid and HDF5 were included. The stock plan does not schedule Parquet for sparse OLTP or fixed-cell updates.
- All scheduled processes exited successfully. Oracle assertions did not terminate any run.

Counters below were emitted by successful processes. A torn observation and a corrupt payload are distinct counters.

- mixed / hdf5, `all_inconsistent` — repeat 1: 2, repeat 2: 4, repeat 3: 7.
- mixed-live / hdf5, `all_inconsistent` — repeat 1: 6, repeat 2: 3, repeat 3: 4.
- cells / hdf5, `torn` — repeat 1: 1777, repeat 2: 1798, repeat 3: 1754.
- The HDF5 cells adapter documents that SWMR readers may observe one part of a multi-cell update before another.

## Durability and comparability

For operations that request durable synchronization, Rust-backed paths use `F_FULLFSYNC` and the SQLite writer connections enable both `fullfsync` and `checkpoint_fullfsync`. These settings request a drive-cache flush. Adapter commit and batching behavior still varies, and the benchmark did not measure power-loss recovery. The earlier macOS PR #43 used SQLite’s previous durability setting and did not evict the macOS page cache before cold reads.

The grid run on this Mac had no memory cap. The archived Linux 10 GB campaign used a different machine, working-set size, memory cap, filesystem and synchronization stack. Read these numbers as a standalone Mac baseline. Use the paired Mac A/B above to compare the two Varlit revisions under the same run conditions.
